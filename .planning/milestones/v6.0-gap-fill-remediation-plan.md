## Implementation Changes

### 1. Give named batches distinct physical filenames

Update [the publication helper](/Users/emadarshadalam/Documents/GitHub/data-harvester/src/data/databento_backfill.py:186):

- When `batch_id` is supplied, pass a deterministic namespace to `LakePublisher`: `"db_" + sha256(batch_id.encode("utf-8")).hexdigest()[:40]`.
- Keep the existing batch ID, writer ID, sequence, borrowed lock, and receipt replay behavior.
- Hashing supports all currently valid batch IDs without exceeding the namespace character or length limits.
- Keep unnamed `TickLakeWriter` publication unchanged.

Add helper-level tests in `tests/data/test_databento.py`: distinct batches at sequence zero produce distinct files; replaying the same batch creates no additional file; an existing unnamespaced receipt still replays successfully.

### 2. Persist original intervals and reconcile receipts before scanning

Update [the gap-fill flow](/Users/emadarshadalam/Documents/GitHub/data-harvester/src/data/gap_fill.py:299):

- Extend `gap_fill_coverage.json` to contain `version: 2`, existing completed `intervals`, and `pending` intervals. Each pending record stores the exact scope, original bounds, batch ID, writer ID, and sequence.
- Continue reading legacy completed coverage formats. Do not infer historical interval bounds from hashed batch IDs.
- Make state writes durable: flush and fsync the temporary file, atomically replace the destination, then fsync its parent directory.
- Under the existing full-fill lock, reconcile matching pending intervals **before occupancy scanning, cost estimates, or downloads**.
- Recover matching publication intents with the borrowed lock. Verify receipt identity, writer, sequence, and files using the existing receipt verification logic.
- For a verified receipt, atomically move its original interval from pending to completed coverage.
- If no receipt or publication intent exists, keep the interval retryable using its original bounds. Exclude those bounds from fresh gap selection to prevent shortened duplicate requests.
- If an intent remains unresolved or verification fails, raise before making external requests.
- Estimate the complete queue of unresolved retries and newly selected gaps before downloading.
- Persist each new interval as pending before its download. After publication succeeds, atomically commit coverage and remove pending state.
- Publish successful empty normalized responses as zero-row named batches. Move the helper's empty-frame shortcut into the unnamed path so empty named batches receive recoverable receipts.

Keep public function signatures and result fields unchanged. Recovered intervals count as zero requests, zero newly written rows, and zero estimated cost in the current invocation.
