# v6.0 Milestone Audit

**Date:** 2026-10-06
**Verdict:** GAPS FOUND, including defects outside the deferred production rewrite.
**Scope:** Phases 50–53 implementation, requirements, integration and offline verification at the candidate SHA above. The production lake rewrite is deliberately excluded from execution and is not counted as a defect. No production lake was opened, copied or rewritten. Application code was not changed by this review.

This review replaces the previous six-line PASSED assessment. Passing the existing milestone tests is insufficient for signoff: the additional interruption, mixed-schema and repeat-request cases below expose defects those tests do not cover.

## Verified behavior

- The real Capital.com WebSocket loop calls the quote parser, awaits the runner callback, and publishes schema-v2 bid/ask rows through the writer.
- Databento `tbbo` normalization keeps `bid_px_00` and `ask_px_00`, drops trade price and size, and publishes schema v2.
- Pure-v2 candles use the bid, and the frontend no longer adds a volume histogram.
- Legacy-v1 and mixed-v1/v2 SQL candle queries work. Mixed candles intentionally use the legacy `price` for old rows until conversion, as the Phase 50 plan specifies. Mixed partitions are skipped by compaction.
- The silence selector applies the 15-minute pre/post and 2-minute regular thresholds separately at session boundaries. Normal weekends, recurring holidays and the tested early closes are excluded.
- A publisher lock already held at the initial check causes refusal before Databento requests, including cost estimation.
- The three public documents describe the new quote columns and silence thresholds.
- On uninterrupted fixture rewrites, valid bid/ask rows retain their values, the old `price` is discarded, null quotes are quarantined, and final receipts and metadata pass the existing fixture checks.

## Findings outside production rewrite execution

### F1 — P1: Schema-v2 crash recovery leaves valid batches pending

**Location:** `src/storage/publication.py:960` in `_recover_pending_publications_locked`.

The ordinary publication and receipt-verification paths now accept v2, but recovery of a staged/promoted batch without a receipt still calls `validate_table_v1(table)`. Its broad exception handler skips the v2 candidate. This affects newly captured quotes even before any existing-lake rewrite.

**Reproduction:** Publish one valid quote and interrupt at the existing `receipt_durability` barrier, after the Parquet promotion but before its receipt. Release ownership and invoke `recover_pending_publications` on that temporary lake. The v1 control recovers one receipt and removes its intent. The identical v2 case recovers zero receipts, leaves one intent and has no receipt. An interruption earlier in promotion can likewise leave v2 data staged rather than visible.

**Fix:** Use version-aware physical-table validation in recovery and extend persistence-boundary/restart tests to real v2 quote batches.

### F2 — P2: Mixed-schema Arrow snapshots silently lose quote values

**Location:** `src/storage/reader.py:1590`, `TickLakeReader.snapshot`.

The SQL reader partitions files by schema, but `snapshot()` constructs an Arrow dataset without an explicit unified schema or per-version normalization. Arrow infers the schema of the first file. In a v1-first mixed snapshot, v2 rows have null `price`, `bid` and `ask`, and their `bid_price`/`ask_price` columns are absent from the returned table. In a v2-first snapshot, the legacy quote columns are not normalized either.

**Reproduction:** Publish one v1 NVDA row and one v2 NVDA row to the same day. SQL and dashboard candles contain both rows. `reader.snapshot(symbols=["NVDA"]).to_table()` returns the v1 column set; the new row retains its identifier but all quote fields in that set are null.

**Fix:** Define and implement mixed-schema snapshot semantics, with tests checking both file orders and preservation of both quote prices. If mixed snapshots are unsupported, fail explicitly instead of returning incomplete values.

### F3 — P2: Sparse completed Databento fills are requested again

**Location:** `src/data/gap_fill.py:279`–`294`, `fill_named_day`.
**Requirement:** QFILL-04.

Selection uses stored tick occupancy alone and never records the successfully requested interval. A legitimate sparse `tbbo` result leaves silent minutes, which the next invocation treats as a fresh hole. The returned `follow_up_requests` value is hardcoded to zero and the current test checks only one invocation.

**Reproduction:** A temporary lake has Capital quotes in every eligible minute except 10:01–10:06 ET. The first fill requests that interval and receives one valid quote at 10:01. The next fill requests 10:02–10:06 again. Empty successful results are also eligible indefinitely.

**Fix:** Persist successful interval coverage independently of row density, scoped to day, dataset, schema and symbol coverage. Only failed requests should remain retryable. Verify reruns after sparse and empty successful responses.

### F4 — P2: Budget checks estimate a different request from the download

**Location:** `src/data/databento_backfill.py:126` and `:356`; actual requests are in `src/data/gap_fill.py:286`.

`estimate_day_cost` still uses 09:00–16:00 ET. Actual selected intervals can span 04:00–20:00 ET, or only a few minutes. The operator authorizes downloads and reports spending using that unrelated estimate. Extended-hours costs can exceed the stated cap; a small inexpensive gap can also be rejected based on a full regular-day estimate.

**Evidence:** Injected metadata client observed 13:00–20:00 UTC on October 2, while empty-day downloads cover 08:00–00:00 UTC. This is a verified range mismatch; no paid API request was made during review.

**Fix:** Select intervals first and estimate each actual interval with the same dataset/schema/symbols before downloading. Account for the intervals actually requested.

### F5 — P2: Exceptional full NYSE closure is not excluded

**Location:** `src/data/gap_fill.py:81`.
**Requirement:** QFILL-03.

The recurring holiday calculation omits January 9, 2025. The selector classifies it as an eligible weekday and requests all three sessions on an empty day. NYSE Group closed its equity and options markets that day for President Carter's National Day of Mourning, as confirmed by the [official ICE announcement](https://ir.theice.com/press/news-details/2024/The-New-York-Stock-Exchange-Will-Close-Markets-on-January-9-to-Honor-the-Passing-of-Former-President-Jimmy-Carter-on-National-Day-of-Mourning/default.aspx). The test claiming comparison with published 2024–2026 dates also omits this closure.

**Fix:** Include exceptional closures for the supported historical range and pin their exclusion in independent calendar fixtures.

### F6 — P2: Post-market quotes receive the wrong session label

**Location:** `src/data/databento_backfill.py:205`.

Normalization chooses only PRE or REG. Newly added post-market requests therefore store, for example, a 17:00 ET quote as REG. Bid and ask themselves are correct.

**Fix:** Classify PRE, REG and POST using the trading day's boundaries, including early-close rules where applicable.

### F7 — P2: The one-named-day operator entry is incomplete

**Location:** `src/data/databento_backfill.py:413`; `src/data/gap_fill.py` has no executable entry.
**Requirement:** QFILL-01 is partially met operationally.

The named-day Python function exists and works, but the executable module still starts a fixed 30-completed-day backward walk. There is no CLI date argument and the public docs provide no named-day command. Even `max_days=1` on the backward walker can visit earlier days when the selected day has no gaps, because only days with requests advance the completed-day count.

**Fix:** Add a documented explicit-date command that processes exactly one requested day and returns after no-gap/closed-day results.

## Rewrite-tool findings, separate from the deferred owner run

These are implementation defects in the shipped tool, not criticism of leaving the production rewrite undone.

### F8 — P1: The backup is copied before exclusive maintenance ownership

**Location:** `src/storage/quote_rewrite.py:313`–`331`.
**Requirement:** REWRITE-04.

The tool probes and releases the publisher lock, copies the lake, and only then acquires the lock and maintenance guard. A writer can publish during that interval. The resulting backup may omit files the tool subsequently rewrites. Additionally, a pre-existing `BACKUP_COMPLETE` marker causes `_copy_lake` to skip copying without binding that marker to the lake identity (`:167`–`179`).

**Reproduction:** An injected copy implementation first copies a one-file lake, then publishes a second v1 file through an ordinary `LakePublisher` before returning. The rewrite completes successfully and converts two files, while the supposedly complete backup contains only one.

**Fix:** Hold exclusive ownership through backup and rewrite, associate the backup manifest with the selected lake/run, and verify complete backup coverage before replacing any live files.

### F9 — P2: Resume loses quarantine records and cumulative counts

**Location:** `src/storage/quote_rewrite.py:332`–`359`, and `:386`–`393`.
**Requirements:** REWRITE-03 and the resume portion of REWRITE-04.

Progress saves only completed paths. Kept/quarantined totals and quarantine rows exist only in memory and are written at the end. After an interruption, finished v2 files are skipped and their previous quarantine information is lost. Retired originals are deleted at successful completion without reconstructing those records.

**Reproduction:** First file contains one valid row and one missing-bid row; second file contains one valid row. Interrupt immediately after the first conversion, then resume. Final report says zero quarantined rows and one kept row; the correct cumulative totals are one quarantined and two kept.

**Fix:** Durably journal per-file counts and quarantine details before marking a conversion finished; reconstruct and verify cumulative reporting on resume.
