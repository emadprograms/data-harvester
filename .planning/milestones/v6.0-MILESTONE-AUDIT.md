## Verified behavior

- The real Capital.com WebSocket loop calls the quote parser, awaits the runner callback, and publishes schema-v2 bid/ask rows through the writer.
- Databento `tbbo` normalization keeps `bid_px_00` and `ask_px_00`, drops trade price and size, and publishes schema v2. Post-market timestamps are labeled POST, not REG.
- Pure-v2 candles use the bid, and the frontend no longer adds a volume histogram.
- Legacy-v1 and mixed-v1/v2 SQL candle queries work. Mixed candles intentionally use the legacy `price` for old rows until conversion. Mixed partitions are skipped by compaction.
- Arrow `snapshot()` uses an explicit union schema. v1-first and v2-first file order both keep stored quote values. `bid_price` is not invented from `price`.
- Schema-v2 batches interrupted at `receipt_durability` recover like v1: one receipt, intent cleared.
- The silence selector applies the 15-minute pre/post and 2-minute regular thresholds separately at session boundaries. Weekends, recurring holidays, 2025-01-09, and the tested early closes are excluded.
- `python -m src.data.gap_fill --date YYYY-MM-DD` processes exactly one named day. Successful sparse or empty `tbbo` intervals are recorded after durable publish (or empty success) and are not requested again — including when the coverage write fails, when the ledger is deleted, and when the publish is interrupted at `receipt_durability`. Interval cost is estimated on the complete queue (unresolved retries plus newly selected gaps) before downloading; the day is refused if the sum exceeds remaining budget. Symbols come from the selected lake's registry.
- Gap fill acquires the publisher lock before Databento work and holds it through download and publish. A live writer already holding the lock is refused before any request.
- On fixture rewrites, valid bid/ask rows retain their values, the old `price` is discarded, null quotes are quarantined, receipts and metadata pass, backup runs under exclusive ownership with size/checksum verification, and resume reconstructs cumulative quarantine from a journal written before swap.
- The three public documents describe the new quote columns, silence thresholds, and the named-day command.

## Post-audit remediation (quick task 261006-hfu, 2026-10-06)

Two findings against `3c35a577` were reproduced, fixed, and pinned with tests. Both were latent in the "Verified" rows above:

- **P1 — same-day intervals shared one filename.** Every named gap-fill batch publishes at `sequence=0`, so two nonempty intervals for the same symbol and UTC date targeted `batch_gap_fill_000000.parquet`. The second raised `BatchCollisionError` after both downloads had been paid for. Fixed with a deterministic `db_<sha256(batch_id)[:40]>` file namespace; writer id, sequence, lock, and receipt replay are unchanged.
- **P2 — a completed request was bought twice.** When publication succeeded and the coverage write failed, the restart re-derived a *shortened* interval (`14:02–14:06` after `14:01–14:06`) and paid for it again. Fixed with a version-2 ledger carrying durable `pending` intervals and reconciliation against verified receipts before occupancy scanning, cost estimation, or any download. Successful empty responses now publish zero-row named batches so "empty means covered" has recoverable evidence.
- **Evidence correction.** The F3/QFILL-04 crash test cited above passed while still issuing a second paid request (it only checked the stored row count). It now asserts request counts, rebuilt bounds, and the byte-identical v1 file, and it fails on the old code.
- **Two review addenda beyond the remediation text:** receipts carry an optional request scope, so a deleted ledger is rebuilt without inferring bounds from a hashed batch id; and the deleted-ledger crash test was strengthened rather than replaced.
- **Gates (final):** `tests/data/test_phase51_gap_fill.py` 50 passed, `tests/data/test_databento.py` 11 passed, four focused suites 71 passed, complete offline suite **1,061 passed, 14 deselected**. Milestone-focused suites 134 passed. A second adversarial review of the fix closed four further robustness gaps (unvalidated batch ids used in path construction, silently dropped ledger entries, unparsed bounds, non-conforming files blocking the shared receipts scan) with 15 more tests, and probed post-compaction recovery and occupancy visibility of the new filenames. No production lake and no paid API.

Deliberately unchanged: the owner-run production rewrite. (The documentation-availability wording and the phase SUMMARY files were already corrected in the reviewed commit, as recorded under Planning and documentation debt.)
