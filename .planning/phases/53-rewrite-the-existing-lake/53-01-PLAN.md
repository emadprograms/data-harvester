# Phase 53 Plan 01: Offline rewrite of a fixture lake

**Goal:** Convert schema v1 files so each kept row's `bid_price` is the old `bid` and `ask_price` is the old `ask`, without inventing a quote from `price`.

**Requirements:** REWRITE-01, REWRITE-02, REWRITE-03, REWRITE-04, REWRITE-05

## Locked decisions

- The tool takes an explicit `lake_root` and `backup_root`. It has no production default. It must not call `resolve_tick_lake_root()` without an override. This checkout does not rewrite the owner's lake.
- Measure the lake and refuse unless free bytes cover a second copy. Tests inject `free_bytes`.
- Copy the lake to the backup first. Write a completion marker only after that copy succeeds. If the copy fails, rewrite nothing.
- If the publisher lock is already held, or a foreign maintenance guard exists, refuse before backup and rewrite. Then hold the publisher lock and `_maintenance/in_progress.json` for the run.
- Keep a row only when both `bid` and `ask` are present and finite and positive. Set `bid_price` from `bid` and `ask_price` from `ask`. Never copy `price`.
- A missing or NaN bid or ask is quarantined and counted. The report may record the old `price` without using it.
- Do not swap a file until kept count plus quarantined count equals the old row count and every kept value matches.
- Record finished relative paths so a resume skips them.
- After a file (or all files of a receipt) is swapped, that receipt's sha256, size, and row count match the new bytes. Recompute `payload_sha256` with `_payload_fingerprint` only when every file on that receipt is schema v2.
- Keep retired v1 bytes until every file has passed. Then delete them and set `lake.json` `schema_version` to 2 with `compatible_versions` including 2.
