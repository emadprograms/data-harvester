# Phase 50 Plan 01: Quote schema and live capture

**Goal:** New Capital.com and Databento rows store `bid_price` and `ask_price` only. The inspection chart builds candles from the bid and does not draw volume.

**Requirements:** QUOTE-01, QUOTE-02, QUOTE-03

## Locked decisions

- New writes are schema v2. Existing schema v1 files stay readable until the owner runs the phase 51 rewrite on their machine.
- Do not compute or store a midpoint. Do not store `price`, `volume`, trade size, bid size, or ask size.
- Capital.com `bid` and `ofr` are stored as-is. Databento `bid_px_00` and `ask_px_00` are stored as-is. The trade price is not a fallback.
- The backup-before-rewrite gate belongs to the phase 51 tool. This checkout does not rewrite a production lake and does not run that tool.
- Existing v1 publisher tests keep writing v1 rows. A row is v2 only when it carries `bid_price` / `ask_price`. The live Capital.com parser and the Databento normalizer are the new-write paths.

## Tasks

1. Add failing tests for QUOTE-01, QUOTE-02, and QUOTE-03, plus a v1 read guard.
2. Add schema v2 and publish it from the live writer without changing the v1 fingerprint.
3. Point the Capital.com parser and the Databento normalizer at that write path.
4. Teach the reader to scan v1, v2, and mixed partitions. v2 candles use `bid_price`. v1 candles keep using `price` so the old suite stays honest.
5. Remove the streaming volume histogram.
6. Let compaction of a pure v2 partition keep v2 columns. Refuse a mixed partition instead of casting it.

## Done when

- `tests/storage/test_phase50_quote_schema.py` passes.
- A Capital.com bid 100.00 / ask 100.04 is stored as those two prices, with no midpoint and no volume column.
- A Databento `tbbo` row stores `bid_px_00` and `ask_px_00` and drops the trade price and size.
- The dashboard candle for that v2 row uses the bid, and `chart.js` does not call `addHistogramSeries`.
- The existing storage suite still passes.
