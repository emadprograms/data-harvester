# Quick Task 260926-p9d: Historical Database Chart Must Open At 09:30 ET (Not 13:30)

## Description
On the dashboard's **🏛️ Historical Database (Archive)** page the chart X-axis and hover legend rendered the
first bar — and the huge opening volume spike — at `13:30 ET`. NYSE/NASDAQ regular trading opens at
**09:30 AM America/New_York**, which is where the opening-bell volume spike belongs. `13:30` is the raw UTC
storage value of the 09:30 EDT open, i.e. the exchange-time conversion silently did not happen while the UI
still labelled everything "ET".

## Root Cause
`src/dashboard/analytics.py` converted storage UTC → exchange time with:

```sql
((timestamp AT TIME ZONE 'UTC') AT TIME ZONE 'America/New_York')::TIMESTAMP
```

That expression is **not deterministic**. Its result depends on two things the query does not control:

1. **The physical type of the `timestamp` column.** Over a `TIMESTAMPTZ` column the first hop produces a
   *naive UTC wall clock*, which the second hop then re-interprets as New York time — a double conversion.
2. **The DuckDB session `TimeZone`**, which DuckDB inherits from the host OS and which resolves the trailing
   `TIMESTAMPTZ -> TIMESTAMP` cast.

On a host running in US Eastern with a tz-aware column (e.g. a database created by an older tz-aware pandas
backfill) the two hops cancel out and the raw UTC wall clock reaches the browser: the 09:30 ET open is
labelled `13:30 ET` and the opening volume spike lands on it. The same shape on a UTC host renders `17:30`,
so the failure mode moved with the machine's timezone.

The front-end compounded the ambiguity: `chart.js` formatted `candle.time` with `toISOString()` /
`getUTC*()` and appended `" ET"`, which is only correct while the backend deliberately shifts the epoch —
an implicit contract nothing enforced.

## Scope of Changes
- **`src/dashboard/analytics.py`**
  - Add an explicit exchange-time layer: `EXCHANGE_TZ`, `TIME_EPOCH_BASIS`, `detect_timestamp_column_type()`,
    `is_tz_aware_column()`, `build_utc_instant_sql()`, `build_exchange_local_sql()`, `build_utc_epoch_sql()`,
    `build_instant_from_exchange_local_sql()`, `build_timestamp_range_clause()`.
  - Build the conversion from the *physical* column type so `TIMESTAMP` (canonical naive UTC) and
    `TIMESTAMPTZ` (legacy) databases render identically, with no implicit cast.
  - `get_historical_candles()` / `get_streaming_candles()` now return `time` as a **true UTC epoch**,
    `time_str` as the NYSE wall clock, plus `timezone`, `time_epoch_basis` and `storage_timestamp_type`.
  - `time_bucket()` still buckets on the exchange-local wall clock, so `1h`/`4h`/`1D` bars snap to NYSE
    hour/day edges (daily bars anchor at exchange midnight = 04:00 UTC in EDT, 05:00 UTC in EST).
- **`src/database/connection.py`**
  - Pin `SET TimeZone = 'UTC'` (`SESSION_TIMEZONE`) on every connection, read-only included, so all
    timestamp casts/comparisons are host-timezone independent.
- **`src/dashboard/static/js/chart.js`**
  - Format X-axis ticks, crosshair badge and legend through `Intl.DateTimeFormat` with an explicit
    `timeZone` (adopted from the API's `timezone` field), dropping all `toISOString()` / `getUTC*()` usage.
  - Date tick marks are only drawn at exchange-local midnight, so a UTC-midnight bar can no longer inject a
    stray date label in the middle of an ET session.
  - O(1) candle lookup by epoch for crosshair/legend; `legend-tz-badge` reflects the API timezone.
- **`src/dashboard/static/index.html`**: bump static asset cache-buster to `?v=nyse-et`.
- **`tools/audit_database_integrity.py`**: same fragile conversion replaced by a type-aware expression;
  session timezone pinned to UTC.
- **`src/database/operations.py`**: document that `query_candlesticks()` stays raw-UTC and that the dashboard
  uses the analytics layer for exchange-local rendering.
- **`requirements.txt`**: add `psutil` (imported by `src/dashboard/analytics.py`).

## Verification
- `tests/dashboard/test_chart_timezone_determinism.py` (37 tests): opening bell + volume spike at 09:30 ET for
  both storage shapes, EST and EDT days, four session timezones, host timezones via subprocess probes
  (`TZ=UTC|America/New_York|Asia/Bahrain`), streaming resampling, connection pinning, front-end contract.
- Existing `tests/dashboard/test_chart_timezone.py` plus the full suite: 262 passed, 5 skipped.
- End-to-end over HTTP against a `TIMESTAMPTZ` archive with `TZ=America/New_York`: API returns
  `time_str=2026-07-15 09:30:00`, `time=1784122200` (13:30 UTC) and the real front-end modules render the
  axis, crosshair and legend as `09:30` / `09:30:00 ET` for the opening bar and the volume spike.
