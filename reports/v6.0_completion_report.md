## Post-audit gap-fill remediation (quick task `261006-hfu`)

Two findings against `3c35a577` were reproduced, fixed, and pinned with tests. Both were latent behind
"verified" language in the milestone audit:

| Finding | Symptom | Fix |
|---|---|---|
| P1 — filename collision | Two nonempty silence intervals for one symbol and UTC day both targeted `batch_gap_fill_000000.parquet`; the second raised `BatchCollisionError` **after both downloads were paid for** | Named batches now publish under a deterministic `db_<sha256(batch_id)[:40]>` file namespace |
| P2 — repeated paid requests | A durable publish whose coverage write failed caused a restart to select a **shortened** interval (`14:02–14:06` after `14:01–14:06`) and pay again | Version-2 coverage ledger with durable `pending` intervals, reconciled against verified receipts before scanning, estimating, or downloading |

The audit's own crash test passed while still issuing that second paid request; it now asserts request counts,
rebuilt bounds, and the byte-identical v1 file. A second adversarial review of the fix found and closed four
further robustness gaps (unvalidated batch ids used in path construction, silently dropped ledger entries,
unparsed bounds, and non-conforming files blocking the shared receipts scan).

Details and evidence: `.planning/quick/261006-hfu-v6-0-gap-fill-remediation-distinct-batch/`.
